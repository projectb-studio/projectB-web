# AI 상세페이지 초안 생성 v2 — 설계 스펙

> 상태: 설계 확정 (`feat/ai-draft-v2`)
> 전제: v1(초안↔발행 격리)은 그대로 둔다. v2 는 그 위에 **품질 레이어**와
> **법정 고지 스캐폴드**를 얹는다.

---

## 1. 왜 v2 인가

v1 은 "AI가 지어낸 사실이 고객에게 도달하지 못하게" 하는 데 성공했다. 하지만
세 가지가 비어 있었다.

1. **카피 품질을 아무도 재지 않았다.** 운영자가 눈으로 보는 것 말고는 게이트가 없다.
2. **레시피 섹션 풀이 좁다.** 리서치한 국내 실무 표준 대비 문제·솔루션 축, 사회적
   증거, 제작 과정, FAQ, 클로징이 통째로 없다.
3. **법정 고지가 없다.** 이게 가장 심각하다. 전자상거래법 상품정보제공고시가
   요구하는 항목이 스펙표에 30~50%만 들어 있고, `[운영자 입력 필요]` 상태로도
   발행이 된다. 고시 일반원칙 3(정보를 못 주면 사유를 제시)에 어긋난다.

---

## 2. 리서치 근거 요약

세 갈래로 병렬 조사했다. 상세는 `docs/research/ai-draft-v2/` 참조.

### 2-1. 국내 실무 표준 (YouTube·블로그)
- 공통 순서: 후킹 → **문제 공감 → 문제 제기 → 솔루션** → 상품 공개 → 특장점 →
  근거(수치/리뷰) → 비교 → 사용법 → 혜택 → 클로징
- 후킹은 "컨셉"이 아니라 **고객이 얻는 이득**이어야 한다
- 핸드메이드는 기능이 아니라 **만드는 과정·만드는 사람**이 유일한 차별점
- AI 티의 정체: 상투어 반복("일상", "고민 없이", "어디에나 어울리는"), 톤 불일치,
  같은 정보의 다른 말 반복

### 2-2. 법정 요건 (공정거래위원회 고시 원문)
- 품목별 필수항목이 다르다. 우리 상품은 **(40) 기타재화 / (17) 주방용품 /
  (5) 침구류·커튼** 세 군에 흩어진다
- **거래조건 정보 5개 대분류는 품목 무관 전 상품 공통 필수**
- 정보를 못 주면 **사유를 제시**해야 한다 → 플레이스홀더 발행은 위반
- 주문제작 청약철회 제한은 **사전 고지 + 서면 동의**가 있어야 유효

### 2-3. 생성 품질 기법 (Anthropic 공식·논문)
- few-shot 예시 3~5개가 톤 통제에 가장 효과적 (공식 문서)
- Structured Outputs 로 스키마 위반 자체를 없앤다 (Haiku 4.5 지원)
- 부정형("~하지 마라")은 모델이 클수록 오히려 못 지킨다 → 품질 지시는 긍정형으로.
  단 **환각 금지 블록은 부정형 유지**(안전 제약을 약화시킬 이유가 없다)
- LLM 판정 편향 3종과 방어: 자기선호(다른 모델로 판정) / 사후합리화(근거를 점수보다
  먼저) / 장황함(길이는 평가 대상 아님을 명시)
- critique 루프는 **초기 1회에 이득이 몰린다**. 상한 2회, 점수가 안 오르면 중단

## 3. 아키텍처

```
                    ┌───────────── 품질 레이어 (v2 신규) ─────────────┐
 facts ──┐          │                                                │
 images ─┼─→ provider.generate ─→ voice-lint (비용 0, 결정론)          │
 feedback┘              ↑         └─→ llm-judge (다른 모델, 유료)      │
                        │                     │                      │
                        └──── 재생성 (bounded ≤2, 최고점 보존) ────────┘
                                              │
                                              ▼
                           recipe.assembleBlocks (v2 확장)
                                              │
                                              ▼
                          pb_product_detail_drafts (pending)
                                              │
                      운영자 검수 ─── approve ──┤
                                              ▼
                    sanitizeBlocks + 플레이스홀더 게이트 (v2 신규)
                                              │
                                              ▼
                                 pb_products.detail_blocks
```

**그래프 라이브러리를 쓰지 않는다.** 분기가 통과/재시도/중단 세 갈래이고 사이클이
단일하다. LangGraph 류를 얹는 것은 이 규모에서 오버엔지니어링이다. (ParkMate에서
같은 판단을 내린 전례가 있다 — 정당한 지점에만 그래프를 쓴다.)

## 4. 레시피 v2

### 4-1. 섹션 구성

`RECIPE_VERSION = "soft-goods-editorial-v2"`

| # | 슬롯 | 종류 | v1 | 비고 |
|---|------|------|----|------|
| S1 | 무드 메인컷 | image | ✅ | |
| S2 | 후킹 한 줄 | voice | ✅ | **정의 변경**: 컨셉 → 고객 이득 |
| S3 | 컨셉·제작 스토리 | voice | ✅ | 핸드메이드 차별점 강조로 프롬프트 조정 |
| **S4** | **문제 공감 → 해결** | **voice** | ❌ | **신규**. 국내 표준의 핵심 축 |
| S5 | 핵심 포인트 2~3 | voice + image | ✅ | |
| S6 | 디테일 갤러리 | image | ✅ | |
| **S7** | **핸드메이드 고지** | fact + voice | ❌ | **신규**. 제작기간·주문제작·개체차 |
| S8 | 스펙표 (마케팅) | fact | ✅ | |
| S9 | 케어 | fact | ✅ | |
| S10 | 배송·교환반품 | fact | ✅ | **확장**: 거래조건 5개 대분류 |
| **S11** | **상품정보제공고시** | **fact 100%** | ❌ | **신규·법정**. AI 생성 절대 금지 |
| **S12** | **클로징 CTA** | voice | ❌ | **신규** |

리뷰·증거 슬롯은 **이번에 넣지 않는다.** `pb_reviews` 연동이 선행되어야 하고,
빈 슬롯을 만들어두면 AI가 채우려 들 위험만 생긴다. (YAGNI)

### 4-2. 고시 품목 매핑

DB에 품목코드 컬럼이 없으므로 tag + 상품명 키워드로 추론하되, **모호하면 고시가
정한 폴백인 (40) 기타재화**를 쓴다. 품목별 필수 행을 전부 스캐폴딩한다.

| 품목 | 판정 | 필수 행 수 |
|------|------|-----------|
| (17) 주방용품 | 이름에 컵/잔/트레이/도마/그릇/보울/접시, 또는 tag=glass | 10 |
| (5) 침구류·커튼 | tag=fabric | 9 |
| (40) 기타재화 | 그 외 전부 (폴백) | 5 |

전 품목 공통으로 v1이 빠뜨렸던 것: **품명 및 모델명 / 제조자 / 품질보증기준 /
A/S 책임자 전화번호**.

### 4-3. 사실값 없을 때

지어내지 않는다. `[운영자 입력 필요]` 로 남기고 `factsNeedingInput` 에 기록한다.
**그리고 이 상태로는 발행되지 않는다** (§6).

## 5. 프롬프트 v2

1. **few-shot 3건 주입** — 카테고리를 섞어(패브릭/메탈/우드) 한 카테고리 패턴에
   과적합되지 않게 한다
2. **품질 지시는 긍정형** — "과장 금지" → "평서형으로 끝내고, 형용사는 문장당 1개 이하"
3. **환각 금지 블록은 부정형 유지** — 안전 제약이므로
4. **Structured Outputs 스키마 강제** — `parseVoice` 의 길이·개수 검증은 남긴다
   (스키마가 minLength/minItems≥2 를 지원하지 않으므로)
5. **상투어 금지 목록 명시** — 리서치에서 나온 실제 표현들

## 6. 품질 게이트 (2층)

### 6-1. voice-lint — 결정론, 비용 0
| 규칙 | 심각도 | 내용 |
|------|--------|------|
| fact-leak | **blocker** | 입력에 없는 수치·소재·관리법·가격 단정 |
| banned-tone | major | 이모지·느낌표 2개↑·과장어 |
| cliche | major | 어느 상품에나 붙는 상투어 |
| length | major | 슬롯 길이·개수 규격 |
| html-shape | major | `<p>` 문단 구조 아님 |
| repetition | minor | 제목 중복·상품명 반복 |

오탐 방지: 소재 동의어(유리↔글라스)와 태그를 근거로 인정한다.

### 6-2. llm-judge — 주관 품질, 유료
- 객관 축(사실침범·구조): binary
- 주관 축(브랜드톤·상품고유성·한국어품질): 0~5, 평균 4.0 이상이어야 통과
- 판정 모델은 생성 모델과 다르게 (`AI_JUDGE_MODEL`, 기본 Sonnet)

### 6-3. 발행 경계 플레이스홀더 게이트 (신규)
`approve` 시점에 블록 안에 `[운영자 입력 필요]` 가 남아 있으면 **422로 발행을
거부**한다. 근거: 고시 일반원칙 3. 이건 품질 문제가 아니라 법 준수 문제다.

## 8. 이번 범위에서 제외 (사용자 결정 필요)

리서치가 찾았지만 DB 마이그레이션·체크아웃 변경이 필요해 **보고만 한다**:

1. **고시 품목코드 컬럼** (`pb_products.notice_category`) — 지금은 키워드 추론
2. **사업자 정보 테이블** — 제조자·A/S 전화번호·품질보증기준의 진짜 출처
3. **주문제작 청약철회 동의 플로우** — 체크아웃에 서면 동의 체크박스 필요
4. **리뷰·증거 슬롯** — `pb_reviews` 연동 선행
5. **DB 시드 상품 16건이 동일한 영문 플레이스홀더** — 한국어 실데이터 교체 필요
